# Inner Circle loading fix — 13 October 2026

Cause verified against the existing production data: circle_journal_sources returns 4,805,252 bytes across 275 Studio records, compared with 159,765 bytes for the first execution page and 128,419 bytes for the six publications. The member app previously awaited all Studio sources after account/core data, per-image signing, and every execution page. Its execution timer refreshed that entire workspace every 15 seconds.

The authenticated shell now loads account and workspace data concurrently. Studio sources are fetched independently only in observation and achievement Studio sections. The execution gallery independently loads/polls its read-only trade feed every 15 seconds; core refresh remains 60 seconds. Neither heavy source blocks shell navigation. Original Journal authentication and MFA/paid checks are preserved. Route changes/sign-out cancel stale updates; no private data is persisted in a new cache. Publication image signing uses one batched request per load. Loading, empty and refresh failures remain distinct. Source refresh actions still refresh the active source list after saves/publications.

No database, image/storage, Journal, billing or access-policy writes. This is frontend loading orchestration only. Validation: parallel-bootstrap and batched-media tests (including signing errors), route/entitlement source gating, existing Journal/Studio/execution/access/portal regressions, root Vite build, design detector, live production route checks. This document reports request/payload improvements, not an invented universal load-time benchmark.
